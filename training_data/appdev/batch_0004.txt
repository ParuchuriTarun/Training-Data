How do I implement idempotency keys for a payment endpoint?

How do I implement rate limiting with Redis that is atomic?
@@@ ASSISTANT
Fixed-window counter with `INCR` + `EXPIRE`, or a Lua sliding window. Return standard headers.

```ts
import { createClient } from "redis";
const redis = createClient({ url: process.env.REDIS_URL });
await redis.connect();

export async function rateLimit(req: any, res: any, next: any) {
  const key = `rl:${req.user?.id ?? req.ip}:${req.baseUrl}`;
  const limit = 100, windowSec = 60;
  const count = await redis.incr(key);
  if (count === 1) await redis.expire(key, windowSec);
  const ttl = await redis.ttl(key);
  res.setHeader("X-RateLimit-Limit", String(limit));
  res.setHeader("X-RateLimit-Remaining", String(Math.max(0, limit - count)));
  res.setHeader("X-RateLimit-Reset", String(Math.floor(Date.now() / 1000) + ttl));
  if (count > limit) {
    res.status(429).setHeader("Retry-After", String(ttl)).json({ error: { code: "rate_limited", message: "Too many requests." } });
    return;
  }
  next();
}
```

- Keys scoped by user, then IP. Different limits per route (auth 10/min, reads 1000/min).
- Fail open for reads, fail closed for auth and payments.
- Test with 150 requests: expect 100 × 200 then 50 × 429 with headers.

How do I handle file uploads to S3 safely with presigned URLs?

  const { filename, contentType, sizeBytes } = req.body;

  if (!key.startsWith(`uploads/${req.user.id}/`)) return res.status(403).json({ error: { code: "forbidden" } });

How do I design a Redis cache without stampedes and stale data?
@@@ ASSISTANT

```ts
import { createClient } from "redis";
const redis = createClient({ url: process.env.REDIS_URL });
await redis.connect();

const inflight = new Map<string, Promise<unknown>>();

export async function getProduct(id: string) {
  const key = `product:${id}:v1`;
  const cached = await redis.get(key);
  if (cached) return JSON.parse(cached);
  let flight = inflight.get(key);
  if (!flight) {
    flight = (async () => {
      const row = await db.query("SELECT * FROM products WHERE id = $1", [id]).then(r => r.rows[0]);
      if (!row) return null;
      await redis.set(key, JSON.stringify(row), { EX: 60 + Math.floor(Math.random() * 20) });
      return row;
    })();
    inflight.set(key, flight);
    flight.finally(() => inflight.delete(key));
  }
  return flight;
}

export async function updateProduct(id: string, patch: Partial<Product>) {
  const row = await db.transaction(async (tx) => {
    return tx.query("UPDATE products SET ... WHERE id = $1 RETURNING *", [id]).then(r => r.rows[0]);
  });
  await redis.del(`product:${id}:v1`);
  return row;
}
```

- Every key has a finite TTL. Jitter TTLs by ±20%.
- Coalescing ensures one DB fetch serves all concurrent misses.
- Invalidate by deleting after the write commits; version keys (`:v1`).
- Short Redis timeout + circuit breaker; fall back to DB if Redis is down.

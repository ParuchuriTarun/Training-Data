How do I use Web Workers for heavy computation without blocking the UI?
@@@ ASSISTANT
Move parsing, indexing, or image work off the main thread.

```ts
// worker.ts
self.onmessage = (e) => {
  const { id, payload } = e.data;
  const result = heavyCompute(payload);
  (self as any).postMessage({ id, result });
};
// main.ts
const worker = new Worker(new URL("./worker.ts", import.meta.url), { type: "module" });
const pending = new Map<string, { resolve: (v: any) => void }>();
worker.onmessage = (e) => { const { id, result } = e.data; pending.get(id)?.resolve(result); pending.delete(id); };
export function runHeavy(payload: any): Promise<any> {
  const id = crypto.randomUUID();
  return new Promise((resolve) => { pending.set(id, { resolve }); worker.postMessage({ id, payload }); });
}
```

- No DOM, `localStorage`, or `window` in workers. Data in, result out.
- Transfer large buffers with `postMessage(msg, [buffer])` to avoid copies.
- Terminate workers on unmount; reuse one worker, do not create per message.
- Errors via `worker.onerror` plus structured `postMessage` errors.

How do I implement infinite scroll with a virtual list?
@@@ ASSISTANT
Fetch pages as the user nears the bottom; render only the visible window.

```tsx
"use client";
import { useEffect, useRef, useState } from "react";

export function InfiniteFeed() {
  const [items, setItems] = useState<string[]>([]);
  const [cursor, setCursor] = useState<string | null>(null);
  const [loading, setLoading] = useState(false);
  const sentinel = useRef<HTMLDivElement>(null);

  useEffect(() => {
    const el = sentinel.current!;
    const io = new IntersectionObserver(async (entries) => {
      if (entries[0].isIntersecting && !loading) {
        setLoading(true);
        const res = await fetch(`/api/feed?cursor=${cursor ?? ""}`);
        const data = await res.json();
        setItems((cur) => [...cur, ...data.items]);
        setCursor(data.nextCursor);
        setLoading(false);
      }
    }, { rootMargin: "400px" });
    io.observe(el);
    return () => io.disconnect();
  }, [cursor, loading]);

  return (
    <div>
      {items.map((i) => <article key={i}>{i}</article>)}
      {loading && <p role="status">Loading more...</p>}
      <div ref={sentinel} />
    </div>
  );
}
```

- `rootMargin` pre-fetches before the user hits the bottom.
- Guard with `loading` so overlapping fetches cannot fire.
- For 10k+ rows, virtualize in addition to paginating.
- Preserve scroll position on route return; announce result counts with `aria-live`.

How do I handle form validation errors from the server in React?
@@@ ASSISTANT
Client validation for instant feedback; server validation as the source of truth; merge field errors back.

```ts
import { useActionState } from "react";

async function loginAction(_prev: any, formData: FormData) {
  const email = String(formData.get("email") ?? "");
  const password = String(formData.get("password") ?? "");
  const res = await fetch("/api/login", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ email, password }) });

}

export function LoginForm() {

  );
```

- Never trust client validation alone; the server re-validates.

How do I implement a modal that is accessible and traps focus?
@@@ ASSISTANT
Focus trap, Escape to close, return focus to the trigger, labelled dialog.

```tsx
"use client";
import { useEffect, useRef } from "react";

export function Modal({ open, onClose, title, children }: { open: boolean; onClose: () => void; title: string; children: React.ReactNode }) {
  const ref = useRef<HTMLDivElement>(null);
  const trigger = useRef<Element | null>(null);

  useEffect(() => {
    if (!open) return;
    trigger.current = document.activeElement;
    const el = ref.current!;
    el.focus();
    const onKey = (e: KeyboardEvent) => {
      if (e.key === "Escape") onClose();
      if (e.key === "Tab") {
        const focusable = el.querySelectorAll<HTMLElement>("button, [href], input, select, textarea, [tabindex]:not([tabindex='-1'])");
        const first = focusable[0], last = focusable[focusable.length - 1];
        if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus(); }
        else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus(); }
      }
    };
    document.addEventListener("keydown", onKey);
    return () => { document.removeEventListener("keydown", onKey); (trigger.current as HTMLElement)?.focus(); };
  }, [open, onClose]);

  if (!open) return null;
  return (
    <div role="presentation" onClick={onClose}>
      <div ref={ref} role="dialog" aria-modal="true" aria-label={title} tabIndex={-1} onClick={(e) => e.stopPropagation()}>
        <h2>{title}</h2>{children}
      </div>
    </div>
  );
}
```

- `aria-modal="true"` + labelled dialog so screen readers announce it.
- Trap Tab within the dialog; return focus on close.
- Test with keyboard only: open, tab through, Escape, verify focus returns.

How do I implement drag and drop for reordering with keyboard support?
@@@ ASSISTANT
HTML5 drag for pointer users; buttons or arrow keys for keyboard users.

```tsx
"use client";
import { useState } from "react";

export function ReorderList({ initial }: { initial: string[] }) {
  const [items, setItems] = useState(initial);
  const [dragIdx, setDragIdx] = useState<number | null>(null);

  function move(from: number, to: number) {
    if (from === to) return;
    setItems((cur) => {
      const next = [...cur];
      const [m] = next.splice(from, 1);
      next.splice(to, 0, m);
      return next;
    });
  }

  return (
    <ol>
      {items.map((item, i) => (
        <li key={item}
          draggable
          onDragStart={() => setDragIdx(i)}
          onDragOver={(e) => e.preventDefault()}
          onDrop={() => { if (dragIdx !== null) move(dragIdx, i); setDragIdx(null); }}>
          <span>{item}</span>
          <button aria-label={`Move ${item} up`} disabled={i === 0} onClick={() => move(i, i - 1)}>Up</button>
          <button aria-label={`Move ${item} down`} disabled={i === items.length - 1} onClick={() => move(i, i + 1)}>Down</button>
        </li>
      ))}
    </ol>
  );
}
```

- Drag is a pointer enhancement; the Up/Down buttons are the keyboard path.
- Announce moves with `aria-live="polite"`.
- Persist order to the server; optimistic update with rollback on failure.

How do I handle loading, empty, and error states in one React component?
@@@ ASSISTANT
One discriminated union; exactly one state active.

```tsx
"use client";
import { useEffect, useState } from "react";

type State =
  | { status: "idle" }
  | { status: "loading"; query: string }
  | { status: "success"; query: string; items: string[] }
  | { status: "empty"; query: string }
  | { status: "error"; query: string; message: string };

export function ProductSearch() {
  const [query, setQuery] = useState("");
  const [state, setState] = useState<State>({ status: "idle" });

  useEffect(() => {
    const q = query.trim();
    if (q.length < 2) { setState({ status: "idle" }); return; }
    const controller = new AbortController();
    const timer = setTimeout(async () => {
      setState({ status: "loading", query: q });
      try {
        const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`, { signal: controller.signal });
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = await res.json();
        setState(data.items.length ? { status: "success", query: q, items: data.items } : { status: "empty", query: q });
      } catch (err) {
        if (err instanceof DOMException && err.name === "AbortError") return;
        setState({ status: "error", query: q, message: "Search failed. Try again." });
      }
    }, 300);
    return () => { clearTimeout(timer); controller.abort(); };
  }, [query]);

  return (
    <div>
      <input value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Search" />
      {state.status === "loading" && <p role="status">Searching for "{state.query}"...</p>}
      {state.status === "empty" && <p>No results for "{state.query}".</p>}
      {state.status === "error" && <p role="alert">{state.message}</p>}
      {state.status === "success" && <ul>{state.items.map((i) => <li key={i}>{i}</li>)}</ul>}
    </div>
  );
}
```

`items` cannot be read when `status` is not `"success"`; TypeScript enforces it.

How do I handle big forms with multiple steps and autosave?
@@@ ASSISTANT
One step at a time, validate per step, autosave drafts to the server.

```tsx
"use client";
import { useState } from "react";

const STEPS = ["Account", "Details", "Review"] as const;

export function Wizard() {
  const [step, setStep] = useState(0);
  const [data, setData] = useState({ name: "", email: "", plan: "pro" });
  const [saving, setSaving] = useState(false);

  async function save(patch: Partial<typeof data>) {
    const next = { ...data, ...patch };
    setData(next);
    setSaving(true);
    try {
      await fetch("/api/draft", { method: "PUT", headers: { "Content-Type": "application/json" }, body: JSON.stringify(next) });
    } finally { setSaving(false); }
  }

  return (
    <div>
      <p>Step {step + 1} of {STEPS.length}: {STEPS[step]} {saving && <span role="status">Saving...</span>}</p>
      {step === 0 && <input value={data.name} onChange={(e) => save({ name: e.target.value })} placeholder="Full name" aria-label="Full name" />}
      {step === 1 && <input value={data.email} onChange={(e) => save({ email: e.target.value })} placeholder="Email" aria-label="Email" />}
      {step === 2 && <p>Review: {data.name}, {data.email}, {data.plan}</p>}
      <button disabled={step === 0} onClick={() => setStep(step - 1)}>Back</button>
      <button disabled={step === STEPS.length - 1} onClick={() => setStep(step + 1)}>Next</button>
    </div>
  );
}
```

- Validate each step before advancing; surface errors inline.
- Autosave debounced (500 ms) so every keystroke is not a request.
- On reload, fetch the draft and resume at the last step.
- Progress indicator uses `aria-current="step"`.
@@@ END

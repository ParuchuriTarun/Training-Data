How do I choose a message broker: Kafka, RabbitMQ, or SQS?
@@@ ASSISTANT
Match the broker to delivery and ordering requirements.

- **Kafka**: log-structured, replayable, ordered per partition. Best for event streaming, CDC, and audit logs. Highest operational cost.
- **RabbitMQ**: flexible routing (fanout, topics, headers), per-message ack, TTL, DLQ. Best for task queues and complex routing.
- **SQS**: managed, FIFO or standard. Best when you want zero broker operations and simple task queues.

Decision rules:
1. Need replay of history or multiple consumers of the same events → Kafka.
2. Need complex routing, per-message TTL, or priority → RabbitMQ.
3. Need managed, simple, serverless → SQS.
4. Exactly-once effects come from idempotent consumers, not the broker.
5. Ordering → Kafka partition key or SQS FIFO with deduplication. Standard queues do not order.
6. Test: publish, kill a consumer mid-processing, restart, assert the side effect happened once.
@@@ END

```http
HTTP/1.1 200 OK

Sunset: Wed, 01 Oct 2027 00:00:00 GMT
Link: <https://docs.example.com/v2>; rel="successor-version"
```

Rules:
1. Additive first. New fields and endpoints never break clients.
2. URL versioning (`/v1`, `/v2`) for breaking changes.
3. Run both versions during the transition.
4. Announce 12 months ahead: header + changelog + direct email.
5. At sunset return `410 Gone` with a pointer, not a generic 404.
6. Track usage; contact the top 10 holders before sunset.
7. Never reuse a removed field name for a different meaning.
8. Contract tests per live version in CI.

How do I implement a scheduled job with a distributed lock?
@@@ ASSISTANT
One leader runs the job; other instances wait.

```ts
import crypto from "node:crypto";

async function withJobLock<T>(jobName: string, fn: () => Promise<T>): Promise<T | null> {
  const token = crypto.randomUUID();
  const acquired = await redis.set(`job:${jobName}:lock`, token, { NX: true, PX: 15 * 60 * 1000 });
  if (acquired !== "OK") return null;
  try { return await fn(); }
  finally {
    const script = `if redis.call("get", KEYS[1]) == ARGV[1] then return redis.call("del", KEYS[1]) else return 0 end`;
    await redis.eval(script, 1, `job:${jobName}:lock`, token);
  }
}
```

- TTL must exceed worst-case job time; heartbeat-extend for long jobs.
- Schedule every minute; the lock ensures one run at a time.
- Log skipped runs. A job that never acquires the lock is a bug.
- Test: run 3 instances; assert the job body executes once per interval.
@@@ END

How do I handle bulk CSV import at scale?
@@@ ASSISTANT
Stream, batch inserts, per-row errors, resumable session.

```ts
async function importCsv(fileId: string, userId: string) {
  let processed = 0, succeeded = 0;
  const errors: { line: number; message: string }[] = [];
  await db.query(`UPDATE imports SET status = 'processing' WHERE id = $1`, [fileId]);
  const stream = getObjectStream(fileId);
  let batch: Row[] = [];
  let line = 1;
  for await (const row of parseCsv(stream)) {
    line++;
    const parsed = RowSchema.safeParse(row);
    if (!parsed.success) { errors.push({ line, message: parsed.error.issues[0].message }); continue; }
    batch.push(parsed.data);
    if (batch.length >= 500) {
      await db.query(`INSERT INTO imported_rows ... ON CONFLICT DO NOTHING`, [batch]);
      succeeded += batch.length; processed += batch.length; batch = [];
      await db.query(`UPDATE imports SET processed_rows = $2, succeeded_rows = $3 WHERE id = $1`, [fileId, processed, succeeded]);
    }
  }
  if (batch.length) await db.query(`INSERT INTO imported_rows ... ON CONFLICT DO NOTHING`, [batch]);
  await db.query(`UPDATE imports SET status = 'done', error_report = $2 WHERE id = $1`, [fileId, JSON.stringify(errors)]);
}
```

- Cap file size and row count; a 2 GB import is a job, not a request.
- Error report downloadable; never a 500 for bad rows.
- Deduplicate on a natural key.
- Test: 100 k rows with 1% bad; assert 99% imported and a retry does not duplicate.

How do I implement multi-tenancy with shared tables?
@@@ ASSISTANT
Shared tables with `tenant_id` on every row, enforced in the database.

```sql
CREATE TABLE orders (
  id bigserial,
  tenant_id uuid NOT NULL,
  order_number text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, id),
  UNIQUE (tenant_id, order_number),
  FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE
);
CREATE INDEX orders_tenant_created_idx ON orders (tenant_id, created_at DESC);
```

Rules:
1. `tenant_id` in the primary key and every unique constraint.
2. Composite FKs: child rows reference `(tenant_id, parent_id)`.
3. Every index starts with `tenant_id`.
4. RLS as backstop: `tenant_id = current_setting('app.tenant_id', true)`.
5. Background jobs set tenant context explicitly per job.
6. Test: two tenants sharing an order number both succeed; tenant-scoped queries never leak.

How do I implement full-text search in Postgres?
@@@ ASSISTANT
`tsvector` + GIN index + `websearch_to_tsquery` for user input.

```sql
CREATE TABLE articles (
  id bigserial PRIMARY KEY,
  title text NOT NULL,
  body text NOT NULL,
  search_tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', title || ' ' || body)) STORED
);
CREATE INDEX articles_search_idx ON articles USING GIN (search_tsv);

SELECT id, title, ts_rank_cd(search_tsv, websearch_to_tsquery('english', $1)) AS rank
FROM articles
WHERE search_tsv @@ websearch_to_tsquery('english', $1)
ORDER BY rank DESC
LIMIT 20;
```

- Generated `tsvector` keeps the index in sync automatically.

- Rank with `ts_rank_cd`; highlight with `ts_headline`.
- For typo tolerance, add `pg_trgm`.
- For large corpora or faceted search, use a dedicated engine instead.

At-least-once delivery + idempotent consumers = exactly-once effects.

Producer -> Queue -> Worker A (marks invisible 30s)
  Worker A crashes before ack -> visibility expires -> job reappears

async function handleJob(job: Job) {

How do I implement leader election with fencing?
@@@ ASSISTANT
Lease from a consensus-aware store; every write carries a fencing term.

Postgres advisory lock:

```sql
SELECT pg_try_advisory_xact_lock(42);
```

```ts
let leader = false;
let term = 0;
async function leaderLoop() {
  while (true) {
    const client = await pool.connect();
    try {
      const { rows } = await client.query("SELECT pg_try_advisory_lock(42)");
      if (rows[0].pg_try_advisory_lock) { leader = true; term += 1; break; }
      await new Promise((r) => setTimeout(r, 2000));
    } finally { client.release(); }
  }
}
```

- Fencing token: storage rejects writes from a stale term.
- Do not trust wall-clock expiry across hosts.
- Prefer managed consensus (etcd/Consul/Raft) for production.
- Test: kill the leader mid-write; assert a new leader within seconds and no stale write.

BEGIN;

- No external calls inside the transaction.
- Retry deadlocks with backoff; never retry validation errors.

How do I implement a circuit breaker for downstream services?
@@@ ASSISTANT
Open after repeated failures, fail fast while open, half-open with one probe.

```ts
type State = "closed" | "open" | "half-open";
class CircuitBreaker {
  private state: State = "closed";
  private failures = 0;
  private openedAt = 0;
  constructor(private readonly threshold = 5, private readonly resetAfterMs = 30_000) {}
  async execute<T>(fn: () => Promise<T>, fallback: () => Promise<T>): Promise<T> {
    if (this.state === "open") {
      if (Date.now() - this.openedAt < this.resetAfterMs) return fallback();
      this.state = "half-open";
    }
    try {
      const result = await fn();
      this.failures = 0; this.state = "closed";
      return result;
    } catch (err) {
      this.failures += 1;
      if (this.failures >= this.threshold) { this.state = "open"; this.openedAt = Date.now(); }
      return fallback();
    }
  }
}
```

- Count only transient failures.
- Fallback must be safe: cached value, queued job, or a clear error.
- Short per-call timeout (2–5 s).
- Half-open allows one probe.
- Metrics on state changes and fallback rate. Alert when open for minutes.
@@@ END

ALTER TABLE invoices FORCE ROW LEVEL SECURITY;

CREATE POLICY tenant_insert ON invoices FOR INSERT WITH CHECK (tenant_id = current_setting('app.tenant_id', true)::uuid);
CREATE INDEX invoices_tenant_created_idx ON invoices (tenant_id, created_at DESC);

```ts
async function withTenant(tenantId: string, fn: (client: Client) => Promise<unknown>) {
  const client = await pool.connect();
  try {
    await client.query("BEGIN");
    await client.query("SELECT set_config('app.tenant_id', $1, true)", [tenantId]);
    const result = await fn(client);
    await client.query("COMMIT");
    return result;
  } catch (err) { await client.query("ROLLBACK"); throw err; }
  finally { client.release(); }
}
```

- `FORCE` matters: without it the table owner bypasses policies.

- The app role must not have `BYPASSRLS` or own the tables.
- Test the negative case in CI.

How do I implement consistent hashing for a cache tier?
@@@ ASSISTANT
Keys and nodes map onto a ring; add/remove moves only `K/N` of the keys.

```ts
import crypto from "node:crypto";
function hash(str: string): number { return crypto.createHash("md5").update(str).digest().readUInt32BE(0); }

class ConsistentHash {
  private ring: { position: number; node: string }[] = [];
  private nodeSet = new Set<string>();
  private readonly replicas = 150;
  addNode(node: string) {
    if (this.nodeSet.has(node)) return;
    this.nodeSet.add(node);
    for (let i = 0; i < this.replicas; i++) this.ring.push({ position: hash(`${node}:${i}`), node });
    this.ring.sort((a, b) => a.position - b.position);
  }
  removeNode(node: string) {
    if (!this.nodeSet.has(node)) return;
    this.nodeSet.delete(node);
    this.ring = this.ring.filter((e) => e.node !== node);
  }
  getNode(key: string): string {
    if (!this.ring.length) throw new Error("no nodes");
    const pos = hash(key);
    let lo = 0, hi = this.ring.length - 1;
    while (lo < hi) { const mid = (lo + hi) >> 1; if (this.ring[mid].position < pos) lo = mid + 1; else hi = mid; }
    return this.ring[lo].node;
  }
}
```

- Virtual nodes (100–200) smooth distribution.
- Use a cryptographic hash for uniformity.
- Test balance: 100 k keys, each node within ±10% of `K/N`.
@@@ END

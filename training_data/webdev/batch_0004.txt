@@@ USER
How do I implement optimistic UI with rollback in React?
@@@ ASSISTANT
Keep a snapshot of the previous state, apply the optimistic change, reconcile or roll back on the response.

```tsx
"use client";
import { useState } from "react";

type Todo = { id: string; title: string; done: boolean };

export function TodoList({ initial }: { initial: Todo[] }) {
  const [todos, setTodos] = useState(initial);
  const [error, setError] = useState<string | null>(null);

  async function toggle(id: string) {
    setError(null);
    const previous = todos;
    setTodos((cur) => cur.map((t) => t.id === id ? { ...t, done: !t.done } : t));
    try {
      const res = await fetch(`/api/todos/${id}/toggle`, { method: "POST" });
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const updated = await res.json();
      setTodos((cur) => cur.map((t) => t.id === id ? updated : t));
    } catch {
      setTodos(previous);
      setError("Could not save. Your change was reverted.");
    }
  }

  return (
    <div>
      {error && <p role="alert">{error}</p>}
      {todos.map((t) => (
        <label key={t.id}>
          <input type="checkbox" checked={t.done} onChange={() => toggle(t.id)} />
          {t.title}
        </label>
      ))}
    </div>
  );
}
```

Rules:
- Always keep the pre-update snapshot for rollback.
- Reconcile with the server response; never trust the optimistic value.
- React 19 `useOptimistic` handles this for you; use it where available.
- Disable the control while a request is in flight or debounce rapid toggles.
- Never leave the optimistic value permanently diverged: on error, refetch.
@@@ END

How do I virtualize a long list so 10,000 rows do not freeze the browser?
@@@ ASSISTANT
Render only the visible rows plus a small overscan, inside a tall scroll container.

```tsx
"use client";
import { useEffect, useRef, useState } from "react";

const ROW_H = 36;
const OVERSCAN = 8;

export function VirtualTable({ rows }: { rows: { id: string; name: string }[] }) {
  const scrollRef = useRef<HTMLDivElement>(null);
  const [scrollTop, setScrollTop] = useState(0);
  const [height, setHeight] = useState(600);

  useEffect(() => {
    const el = scrollRef.current!;
    const update = () => setHeight(el.clientHeight);
    update();
    const ro = new ResizeObserver(update);
    ro.observe(el);
    return () => ro.disconnect();
  }, []);

  const start = Math.max(0, Math.floor(scrollTop / ROW_H) - OVERSCAN);
  const visibleCount = Math.ceil(height / ROW_H) + OVERSCAN * 2;
  const end = Math.min(rows.length, start + visibleCount);
  const slice = rows.slice(start, end);

  return (
    <div ref={scrollRef} style={{ height: 600, overflowY: "auto", position: "relative" }}
      onScroll={(e) => setScrollTop((e.target as HTMLDivElement).scrollTop)}>
      <div style={{ height: rows.length * ROW_H }}>
        {slice.map((row, i) => (
          <div key={row.id} style={{ position: "absolute", top: (start + i) * ROW_H, height: ROW_H, width: "100%" }}>
            {row.name}
          </div>
        ))}
      </div>
    </div>
  );
}
```

Rules:
- Variable row heights need a measurement cache.
- Keep the active row in the rendered window for keyboard navigation.
- For very large data, fetch pages on scroll instead of loading everything.
- TanStack Virtual does this; use it once the hand-rolled version works.

Why does 100vh overflow on mobile Safari and how do I fix full-screen layouts?
@@@ ASSISTANT
`100vh` includes the area under the collapsible address bar. Use dynamic viewport units.

```css
.hero { height: 100vh; height: 100dvh; }
@supports (height: 100svh) {
  .hero { height: 100svh; }
  .modal { height: 100svh; }
}
```

- `svh`: stable, always excludes dynamic chrome. Best for layouts that must not jump.
- `dvh`: changes as chrome shows/hides. Best for full-bleed heroes.
- `lvh`: largest possible value.

Test on a real device: iOS Safari and Chrome Android both collapse chrome on scroll. For modals, use `100svh` with internal `overflow-y: auto`.

How do I implement a search box with debounce, abort, and stale-result protection?
@@@ ASSISTANT
Debounce, abort the previous request, and ignore out-of-order responses.

```tsx
"use client";
import { useEffect, useRef, useState } from "react";

export function SearchBox() {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<string[]>([]);
  const requestId = useRef(0);

  useEffect(() => {
    if (query.trim().length < 2) { setResults([]); return; }
    const id = ++requestId.current;
    const controller = new AbortController();
    const timer = setTimeout(async () => {
      try {
        const res = await fetch(`/api/search?q=${encodeURIComponent(query)}`, { signal: controller.signal });
        const data = await res.json();
        if (requestId.current !== id) return;
        setResults(data.items);
      } catch (err) {
        if (err instanceof DOMException && err.name === "AbortError") return;
        setResults([]);
      }
    }, 300);
    return () => { clearTimeout(timer); controller.abort(); };
  }, [query]);

  return (
    <div>
      <input type="search" value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Search products" />
      <ul>{results.map((r) => <li key={r}>{r}</li>)}</ul>
    </div>
  );
}
```

- Debounce 250–400 ms, minimum length 2.
- Abort on cleanup; also keep a request id as a second guard.
- Show loading with `role="status"` and keep previous results while fetching.
- Cache repeated queries with `staleTime` in TanStack Query.

How do I keep filters in the URL so links are shareable and Back works?
@@@ ASSISTANT
URL is the source of truth for shareable state.

```tsx
"use client";
import { useRouter, useSearchParams } from "next/navigation";
import { useCallback } from "react";

export function FilterBar() {
  const router = useRouter();
  const params = useSearchParams();
  const status = params.get("status") ?? "all";
  const sort = params.get("sort") ?? "newest";
  const page = Math.max(1, Number(params.get("page") ?? 1));

  const update = useCallback((patch: Record<string, string>) => {
    const next = new URLSearchParams(params.toString());
    for (const [k, v] of Object.entries(patch)) {
      if (!v) next.delete(k); else next.set(k, v);
    }
    router.push(`?${next.toString()}`, { scroll: false });
  }, [params, router]);

  return (
    <div>
      <select value={status} onChange={(e) => update({ status: e.target.value, page: "1" })}>
        <option value="all">All</option><option value="active">Active</option>
      </select>
      <select value={sort} onChange={(e) => update({ sort: e.target.value })}>
        <option value="newest">Newest</option><option value="price-asc">Price low to high</option>
      </select>
      <button onClick={() => update({ page: String(page + 1) })}>Next</button>
    </div>
  );
}
```

- Validate params on the server; unknown values fall back to defaults.
- Reset page to 1 when a filter changes.
- Use `router.replace` for typing, `router.push` for deliberate changes.
- SSR reads the same params so shared links render identically.

How do I implement theme toggle with system preference and no flash?
@@@ ASSISTANT
Blocking script in `<head>` sets the class before first paint.

```tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: `

            if (t === "dark" || (!t && matchMedia("(prefers-color-scheme: dark)").matches)) {
              document.documentElement.classList.add("dark");
            }
          } catch (e) {}
        `}} />
      </head>
      <body>{children}</body>
    </html>
  );
}
```

```tsx
"use client";
import { useEffect, useState } from "react";

export function ThemeToggle() {
  const [dark, setDark] = useState(false);
  useEffect(() => { setDark(document.documentElement.classList.contains("dark")); }, []);
  function toggle() {
    const next = !dark;
    setDark(next);
    document.documentElement.classList.toggle("dark", next);
    localStorage.setItem("theme", next ? "dark" : "light");
  }
  return <button onClick={toggle} aria-pressed={dark}>{dark ? "Light mode" : "Dark mode"}</button>;
}
```

- No flash: the script runs before render.
- Default to `prefers-color-scheme` when no stored choice.
- Style with CSS variables; components never hard-code colors.

How do I implement file uploads with progress and chunked resume?
@@@ ASSISTANT
XHR for progress, chunked puts with retry, persisted session for resume.

```ts
async function uploadFile(file: File, onProgress: (pct: number) => void, signal: AbortSignal) {
  const CHUNK = 5 * 1024 * 1024;
  const session = await createSession(file.name, file.size);
  for (let off = 0; off < file.size; off += CHUNK) {
    if (signal.aborted) throw new DOMException("aborted", "AbortError");
    const slice = file.slice(off, Math.min(off + CHUNK, file.size));
    let attempts = 0;
    while (true) {
      try { await putChunk(session.id, off, slice, signal); break; }
      catch (err) { attempts++; if (attempts >= 3) throw err; await new Promise(r => setTimeout(r, 500 * attempts)); }
    }
    onProgress(Math.min(100, ((off + slice.size) / file.size) * 100));
  }
  return completeSession(session.id);
}
```

Server: `POST /uploads` creates a session; `PUT /uploads/:id/chunks/:offset` is idempotent by offset; `POST /uploads/:id/complete` verifies size and checksum. Persist `{ sessionId, uploadedOffsets[] }` in IndexedDB for resume after refresh.

Why does a plain Map as a cache leak memory in a long-running worker?
@@@ ASSISTANT
It grows without bound. At 40 entries/min, even small entries fill the heap in days.

```ts
const cache = new Map<string, ParsedReport>();
// Every parsed report is retained forever. OOM in ~10 days.
```

Fixes in order:
1. Measure hit rate. Below ~20%, delete the cache.
2. If hit rate is real, bound it: LRU with `max`, `maxSize`, and `ttl`.
3. Or cache on disk (content-addressed file, atomic write, TTL cleanup). Disk cache gives reuse without heap retention.

Add a regression test: parse 200 reports and assert heap growth < 50 MB. Alert when heap exceeds 80% for 5 minutes.

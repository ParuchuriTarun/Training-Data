Write a JavaScript function to debounce a search input and fetch results with proper error handling.
@@@ ASSISTANT
```javascript
function debounce(fn, delay = 300) {
  let timer;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

let controller = null;

async function search(query) {
  const results = document.querySelector('#results');
  if (!query.trim()) {
    results.textContent = '';
    return;
  }

  // Cancel the previous request so old answers never overwrite new ones.
  if (controller) controller.abort();
  controller = new AbortController();

  try {
    const res = await fetch(`/api/search?q=${encodeURIComponent(query)}`, {
      signal: controller.signal,
    });
    if (!res.ok) throw new Error(`Server returned ${res.status}`);
    const items = await res.json();

    results.replaceChildren(
      ...items.map((item) => {
        const li = document.createElement('li');
        li.textContent = item.title; // textContent avoids HTML injection
        return li;
      })
    );
  } catch (err) {
    if (err.name === 'AbortError') return; // expected when typing fast
    results.textContent = 'Something went wrong. Please try again.';
    console.error(err);
  }
}

document.querySelector('#q').addEventListener('input', debounce((e) => search(e.target.value), 300));
```

Why each part matters:
- **Debounce** waits until the user pauses typing, so you send one request instead of one per key.
- **AbortController** cancels the older request, which prevents a slow old response from replacing a newer one.
- `fetch` does not throw on HTTP errors like 404 or 500, so check `res.ok` yourself.
- `encodeURIComponent` protects the URL, and `textContent` protects the page from XSS.

```jsx
  const [loading, setLoading] = useState(true);
```

Explain React useState and useEffect with a counter and a timer example, including common mistakes.
@@@ ASSISTANT
`useState` stores a value that, when changed, re-renders the component. `useEffect` runs code after rendering, for things outside React like timers, subscriptions and network calls.

```jsx
import { useEffect, useState } from "react";

export default function Stopwatch() {
  const [seconds, setSeconds] = useState(0);
  const [running, setRunning] = useState(false);

  useEffect(() => {
    if (!running) return;
    const id = setInterval(() => {
      setSeconds((s) => s + 1); // functional update: always uses the latest value
    }, 1000);
    return () => clearInterval(id); // cleanup runs before the next effect and on unmount
  }, [running]);

  return (
    <div>
      <h2>{seconds}s</h2>
      <button onClick={() => setRunning((r) => !r)}>{running ? "Pause" : "Start"}</button>
      <button onClick={() => { setRunning(false); setSeconds(0); }}>Reset</button>
    </div>
  );
}
```

Common mistakes:
1. **Mutating state directly.** `items.push(x)` does not trigger a re-render. Use `setItems([...items, x])`.
2. **Using the old value in a timer.** `setSeconds(seconds + 1)` inside `setInterval` keeps adding to a stale number; use `setSeconds(s => s + 1)`.
3. **Forgetting cleanup.** Without `clearInterval` the timer keeps running after the component is gone.
4. **Missing dependencies.** Every value from the component that the effect uses should be in the dependency array. The `eslint-plugin-react-hooks` rule warns you about it.

```javascript
  const note = notes.find((n) => n.id === Number(req.params.id));
  if (!note) return res.status(404).json({ error: "Note not found" });
  if (typeof req.body.text !== "string" || req.body.text.trim() === "") {
```

Show me how to center a div both horizontally and vertically, and explain why my margin: auto only works horizontally.
@@@ ASSISTANT
Three reliable ways:

```css
/* 1. Flexbox on the parent (most common) */
.parent { display: flex; justify-content: center; align-items: center; min-height: 100vh; }

/* 2. Grid on the parent (shortest) */
.parent { display: grid; place-items: center; min-height: 100vh; }

/* 3. Absolute positioning */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

Why `margin: auto` only centers horizontally: in normal block layout, auto side margins share the free horizontal space, but a block's height is determined by its content, so there is no "free vertical space" to share. Inside a flex or grid container, though, auto margins work in both directions:

```css
.parent { display: flex; min-height: 100vh; }
.child { margin: auto; } /* now centered vertically and horizontally */
```

Common trap: the parent needs a height (`min-height: 100vh` or a fixed height), or there is nothing to center within.

Explain the difference between var, let and const in JavaScript, and what == vs === does.

```javascript
console.log(a); // undefined  (var is hoisted and initialised as undefined)
```

Write a small TypeScript example with types, interfaces, generics and a type guard.

```typescript
interface User {
  id: number;
  name: string;
  email?: string; // optional
}

type ApiResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string };

function isUser(value: unknown): value is User {
  return (
    typeof value === "object" &&
    value !== null &&
    typeof (value as User).id === "number" &&
    typeof (value as User).name === "string"
  );
}

async function fetchUser(id: number): Promise<ApiResult<User>> {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) return { ok: false, error: `HTTP ${res.status}` };
    const json: unknown = await res.json();
    return isUser(json) ? { ok: true, data: json } : { ok: false, error: "Unexpected data shape" };
  } catch (e) {
    return { ok: false, error: e instanceof Error ? e.message : "Unknown error" };
  }
}

// Generic helper: works with any array type
function groupBy<T, K extends string | number>(items: T[], key: (item: T) => K): Record<K, T[]> {
  const out = {} as Record<K, T[]>;
  for (const item of items) {
    (out[key(item)] ||= []).push(item);
  }
  return out;
}

const result = await fetchUser(1);
if (result.ok) {
  console.log(result.data.name); // TypeScript knows data exists here
} else {
  console.error(result.error);
}
```

Key ideas:
- A **discriminated union** (`ok: true | false`) forces callers to check the result before using `data`.
- Data from the network is `unknown`, not `any`. A **type guard** (`value is User`) proves the shape at run time.
- **Generics** (`T`, `K`) keep the helper reusable while preserving types.

How do I use localStorage to save and load a todo list in JavaScript safely?

```javascript
const KEY = "todos:v1";

function loadTodos() {
  try {
    const raw = localStorage.getItem(KEY);
    const parsed = raw ? JSON.parse(raw) : [];
    return Array.isArray(parsed) ? parsed : [];
  } catch {
    return []; // corrupted data or storage blocked
  }
}

function saveTodos(todos) {
  try {
    localStorage.setItem(KEY, JSON.stringify(todos));
  } catch (err) {
    console.warn("Could not save", err); // private mode or storage full
  }
}

let todos = loadTodos();

function addTodo(text) {
  todos = [...todos, { id: crypto.randomUUID(), text, done: false }];
  saveTodos(todos);
}

function toggleTodo(id) {
  todos = todos.map((t) => (t.id === id ? { ...t, done: !t.done } : t));
  saveTodos(todos);
}
```

Things to know:

- Wrap reads and writes in `try/catch`; they can throw in private windows or when the quota (about 5 MB) is full.
- Version your key (`todos:v1`) so a future format change does not break old data.
- Never store passwords or tokens in `localStorage`; any script on the page can read it.

My fetch request fails with a CORS error. What is CORS and how do I fix it?
@@@ ASSISTANT
CORS (Cross-Origin Resource Sharing) is a browser rule: a page from one origin (for example `http://localhost:5173`) may only read responses from another origin (`http://localhost:3000`) if the server says so with an `Access-Control-Allow-Origin` header. The error is not a bug in your frontend code; the browser is blocking the response because the server did not allow it.

The fix belongs on the **server**. With Express:

```javascript
const cors = require("cors"); // npm install cors

app.use(cors({ origin: "http://localhost:5173" }));
```

Without the library:

```javascript
app.use((req, res, next) => {
  res.setHeader("Access-Control-Allow-Origin", "http://localhost:5173");
  res.setHeader("Access-Control-Allow-Headers", "Content-Type, Authorization");
  res.setHeader("Access-Control-Allow-Methods", "GET,POST,PUT,DELETE,OPTIONS");
  if (req.method === "OPTIONS") return res.sendStatus(204); // answer the preflight request
  next();
});
```

During development you can also use a proxy so the browser sees one origin. In Vite:

```javascript
// vite.config.js
export default { server: { proxy: { "/api": "http://localhost:3000" } } };
```

Avoid `Access-Control-Allow-Origin: *` on APIs that use cookies or private data. List the exact origins you trust.

@@@ USER
Explain async/await and Promises in JavaScript with parallel and sequential examples.
@@@ ASSISTANT
A Promise represents a value that will arrive later. `async/await` is syntax that lets you write Promise code in a straight line.

```javascript
const wait = (ms, value) => new Promise((resolve) => setTimeout(() => resolve(value), ms));

// Sequential: total time = 300 + 200 = about 500 ms
async function sequential() {
  const a = await wait(300, "A");
  const b = await wait(200, "B");
  return [a, b];
}

// Parallel: total time = the slowest = about 300 ms
async function parallel() {
  const [a, b] = await Promise.all([wait(300, "A"), wait(200, "B")]);
  return [a, b];
}

// Keep going even if one fails
async function tolerant() {
  const results = await Promise.allSettled([wait(100, "ok"), Promise.reject(new Error("boom"))]);
  return results.map((r) => (r.status === "fulfilled" ? r.value : `failed: ${r.reason.message}`));
}

(async () => {
  console.time("seq");  await sequential(); console.timeEnd("seq");
  console.time("par");  await parallel();   console.timeEnd("par");
  console.log(await tolerant());
})();
```

Rules of thumb:
- Use `await` one after another only when the second call needs the first result. Otherwise start both and use `Promise.all`.
- `Promise.all` rejects as soon as any promise fails; `Promise.allSettled` waits for all and reports each outcome.
- Always handle errors with `try/catch` around `await`, or `.catch()` on the promise.
- `await` inside `array.forEach` does not wait. Use a `for...of` loop or `Promise.all(array.map(...))`.

@@@ USER
How do I protect a web app against SQL injection and XSS?
@@@ ASSISTANT
**SQL injection** happens when user input is pasted into a query string. The fix is parameterized queries.

Vulnerable:

```javascript
db.query(`SELECT * FROM users WHERE email = '${email}'`); // an input like ' OR '1'='1 breaks it
```

Safe (Node `pg` driver):

```javascript
db.query("SELECT * FROM users WHERE email = $1", [email]);
```

The driver sends the SQL and the value separately, so the value can never become code. ORMs and query builders do this for you as long as you do not concatenate raw strings.

**XSS (cross-site scripting)** happens when user-provided text is inserted into the page as HTML.

Vulnerable:

```javascript
element.innerHTML = comment; // a comment like <img src=x onerror=...> runs code
```

Safe:

```javascript
element.textContent = comment;
```

Additional defenses:
- Frameworks like React escape values in `{}` by default; avoid `dangerouslySetInnerHTML` unless the HTML is sanitized (for example with DOMPurify).
- Send a Content Security Policy header to limit which scripts may run.
- Set cookies with `HttpOnly`, `Secure` and `SameSite=Lax` so scripts cannot read your session cookie.

@@@ USER
Write a basic SQL schema for a blog (users, posts, comments) and useful queries.
@@@ ASSISTANT
```sql
CREATE TABLE users (
  id         INTEGER PRIMARY KEY,
  username   TEXT NOT NULL UNIQUE,
  email      TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE posts (
  id         INTEGER PRIMARY KEY,
  author_id  INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  title      TEXT NOT NULL,
  body       TEXT NOT NULL,
  published  INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE comments (
  id         INTEGER PRIMARY KEY,
  post_id    INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  body       TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Index the columns you filter and join on.
CREATE INDEX idx_posts_author ON posts(author_id);
CREATE INDEX idx_comments_post ON comments(post_id);
```

Useful queries:

```sql
-- Latest 10 published posts with author name and comment count
SELECT p.id, p.title, u.username, COUNT(c.id) AS comments
FROM posts p
JOIN users u ON u.id = p.author_id
LEFT JOIN comments c ON c.post_id = p.id
WHERE p.published = 1
GROUP BY p.id
ORDER BY p.created_at DESC
LIMIT 10;

-- Users who never posted
SELECT u.username
FROM users u
LEFT JOIN posts p ON p.author_id = u.id
WHERE p.id IS NULL;
```

Notes:
- `LEFT JOIN` keeps posts that have zero comments; an `INNER JOIN` would drop them.
- `ON DELETE CASCADE` removes comments automatically when a post is deleted.
- Syntax is SQLite-flavoured; in PostgreSQL use `SERIAL`/`GENERATED ... AS IDENTITY`, `BOOLEAN` and `TIMESTAMPTZ`.
@@@ END
